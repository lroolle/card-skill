Your agent answers with cards. You judge each one.

A skill for coding agents such as Claude Code. The agent lays its answer out as a board: one claim per card, at most one ask. Your reply goes back as data, one line per card.

Two things the sample does not show

A changed card says so, and keeps what it said before

The agent revises a card instead of writing a new answer. The card keeps its number, gets a version, and shows its earlier versions struck through. An answer you gave to an old version is flagged, not reused.

Card 25 of this project's design review, at its third version.

A card draws what it talks about

The agent writes which thing leads to which; the page draws the boxes and the arrows. A screenshot or twenty lines of a file go into the card the same way, inside the one HTML file.

Install

# 1. Copy the skill. A real copy, not a link.
git clone https://github.com/{{REPO}}
cp -R {{NAME}}/skill ~/.claude/skills/{{NAME}}

# 2. See a board without an agent.
cd {{NAME}}
node skill/bin/cards.mjs render design-review
node skill/bin/cards.mjs serve

Then ask for something that ends in a decision:

Compare three queues for our ingest service and let me pick. Answer with cards.

The skill tells the agent when a board is earned and when prose is better. Most answers should stay prose.

Node 18 or later. No dependencies. The copy does not update itself: copy it again after a pull. cards --version says which build you have.

What it does not do

  • It is not for one answer. A board for one paragraph is too much. Use it for several judgments, a decision only you can make, or work that spans turns.
  • It is not checked on a real phone. The tests run in Chromium, Firefox and WebKit on a desktop. The list is in STATUS.md.
  • It runs no service. A board is a file on your disk. A published board is a static page; a reader copies the reply and sends it to you.
